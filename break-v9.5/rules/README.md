## 可以直接在這份repo重現

需要Node.js（本批Node 24.15.0）及Python 3。沒有新增套件或網路需求。從`break-v9.5/`執行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 rules/rebuild.py
node rules/core.test.js
```

`rebuild.py`會在暫存目錄完整執行來源快照的共用規則建檔／驗證、全卡建檔／驗證及契約測試，再與`data/`逐位元組比對。要有意更新資料時使用`--write`，完成後再檢查差異與指紋。`source/`含14個必要來源及作者工具檔案，`data/manifest.json`記錄全部來源及六份資料結果的SHA-256；不依賴聊天外層工作目錄。

## 本批實作

- `core.js`：獨立JavaScript共用結算核心，Node可載入，亦保留瀏覽器入口供後續整合。
- 三層權限：事件打出、技能使用、分段動作分開。匹配玩家、來源、階段、角色等範圍；缺少必要判定資訊會停止，不默認允許。
- 21種動作節點及相關條件／選取：支付、抽牌、移動、回收、登場、數值、監聽、限制、保護與跳階段等；每種仍有下述限制。
- 實體ID與角色身分代次分開；替換不繼承原角色加值，Guts自然露出不產生登場事件。
- 已生成監聽獨立於來源；待處理角色被動若來源進入隱藏區或技能被無效，會取消。
- 同時觸發先回合玩家、再對方；各玩家可以選自己的觸發順序。先完成當前技能才處理佇列。
- 回合／下個對手回合／本抽牌階段的期限分開；跳階段取消舊窗口待處理觸發，當前技能後段繼續。
- Loss進入獨立流程，先清除球總值，再處理Loss觸發，清理效果後停在間隔入口；不觸發一般回合結束。
- 狀態快照含實體、效果、佇列、限次及已作選擇；資料版本、對練設定及實驗／正式模式不同時拒絕還原。這是本機可信快照，不是多人授權或同步協定。
- `view(player)`只顯示該玩家手牌，對手手牌與牌庫僅提供張數；公開角色含目前參數與Guts實體。

目前正式執行核准卡片為0。測試用`sandbox`模式可執行已支援且無待釐清旗標的實際資料；`live`模式拒絕尚未核准的技能。核心沒有卡號專用效果分支，也不在執行時閱讀日文或判例。

## 重要界線

- 關鍵字本批只實作ワンタッチ／one_touch；其餘關鍵字明確停止，不當成已成功執行。PR-081支付資料已修正，但含blockout的完整卡片仍未由此核心放行。
- 暫不處理改名登場、非自身登場型的角色被動、逐區精確Guts費用、交換、翻牌／查看選牌、永久固定值、來源加值上限或連續匹配的全體效果。含這些資料或未知機制會回報待覆核；尚未核准卡片不進入正式遊戲。
- P04-070全體保護的成員匹配界線仍未定；四個印刷差異、P03-047及事件完全無變化界線仍保留。事件技能已失效的放置情境有獨立處理，未將所有無變化事件一律允許。
- 無中攔時的特殊側攔例外暫回待覆核，沒有套用「一律禁止」的泛用裁定。
- `advancePhase`是給遊戲控制器提供已確認階段／步驟的入口，不是完整回合流程驗證器。規則抽牌時點、必要登場、判定、側攔清理、間隔補牌、計分／勝負等仍待控制器整合；本批不是完整比賽引擎。
- 玩家選擇目前由同步`choose(request)`提供。無回覆或非法回覆會停止並還原此操作；尚未有手機畫面等待回覆／手動翻牌介面。快照只在結算邊界使用，不能代替非同步決策的重播協定。
- 官方階段預設不延伸；`practiceDrawBeforeReceive:true`會按資料的對練覆寫，開放抽牌事件在接球自由步驟使用，不延伸手牌主動技能、不改卡面圖示。舊畫面仍保留既有設定。

## 測試範圍

`core.test.js`有54個情境，使用封存的真實卡片資料及限定機制局面。包括岩泉限制來源、抽牌階段限制、黑川離場後監聽、跨區六Guts、跨卡號同名限次、赤木六種來球、P01-088可選抽牌後的手牌條件、同時觸發、ワンタッチ保護／跳階段／後段、來源失效、Loss觸發及快照還原等。

其中一個情境執行20個種子、共600次狀態操作，每次還原後重做並比較完整狀態及牌張守恆。這不是600局比賽，也沒有驗證全部602則判例。

原遊戲要求的build、3,000局fuzz及每組300局對戰回歸通過；原引擎／UI／建置頁指紋不變。下一批處理非同步選擇及舊引擎介面，再逐機制將現有47卡接入並核准；不要一次切換全卡或同時讓兩套邏輯重複結算。

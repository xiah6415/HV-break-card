# 數值模式與嚴格模式

網頁預設數值模式，並保存選擇。數值模式可組牌541卡；嚴格模式可組牌212卡（183無技能＋既有29技能），仍拒絕329張未自動化技能卡。40張與Event最多8張的牌組限制、未知卡號拒絕、雙方分享連結／JSON匯入均維持。切換嚴格模式會停用不符合的自訂牌組選項，保留牌組資料，不靜默刪掉或替換卡片。

自動化技能仍只有22張完整SHA核准與7張舊流程，後者有既有部分效果限制；沒有新增技能核准。未自動化卡在圖卡與詳情標示「技能未自動化」。角色按印刷數值使用；未自動化Event可在印刷階段由玩家放入Event區，記錄放置並由玩家手動處理效果，不執行未核准程序。AI按角色數值操作，不猜測未自動化技能；不自行把沒有數值用途的未自動化Event當作有效加值技能。

數值模式在各階段自由操作與結束回合確認時提供「手動」：

- 選雙方場上角色，調整發／攔／接／舉／攻±1；「－」不可改成數值。
- 調整來球總值±1。
- 我方或AI抽1；我方棄牌選實體，AI棄牌由AI選，不展示其私有手牌。

手動操作由玩家判定技能條件與費用，這個面板不是所有技能的自動裁定器。操作會進對局紀錄與Undo決策歷史，使用既有實體移牌；未開放在對手回合或共用技能待選中直接改局。數值修正以實體角色綁定，到本回合結束或角色離場失效；既有自動防降保護仍生效。手動抽／棄牌是玩家修正，不自動模擬未實作技能的額外監聽鏈。

事件與手動修正後、正式交棒前，發球與舉攻重新讀最終值，避免畫面更新卻送出舊來球。Loss、手動結束回合、翻牌確認、過場1秒／手動設定，以及手機面板不遮手牌均保留。

## 資料與程式界線

- DEF與runtime供應541卡代表印刷身分，未核准的技能程序全部剝除；這不表示541技能能自動執行。原始rules/data仍全部runtime_approved=false，22張由approvals覆寫。
- 4張卡文版本差異的印刷參數已確認一致，數值模式採代表卡圖身分，不選定其技能版本核准。詳細卡文仍可查閱。
- card-library.json的playable與counts.playable繼續表示嚴格模式支援；numeric模式不改寫成新的技能核准。
- JSON／分享解析接收`{mode:'numeric'}`或`{mode:'strict'}`；Game與UndoSession使用相同mode。為相容既有模擬與呼叫，程式API未指定mode時保持strict，網頁預設numeric。
- coverage／batch索引中的in_runtime_catalog現在表示印刷身分已載入；125技能候選仍未核准，不能把runtime metadata存在當作正式技能通過。
- 權限來源完整改造仍排REVIEW-PLAN第5步；14張有限事件尚未恢復。完整SHA＋固定舊技能白名單的核准來源改造，不應與數值模式可組牌混淆。

主要驗證入口：numeric.test.js、numeric-undo.test.js、numeric-e2e.js，以及既有嚴格模式的單元／模擬／瀏覽器回歸。最新實際通過範圍與公開版本見memory.md與outputs/BREAK-numeric-mode-update.md。
